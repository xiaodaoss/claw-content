## 正文

用 AI 写代码，最怕的不是它写不出来，而是它写出来跑不通，你还不知道怎么让它改对。

试了十几个模型，踩了无数坑之后，总结出 **3 个真正有效的技巧**。不需要学什么提示词工程，看完直接套用。

### 技巧一：给 AI 一个"身份锚定"

不要直接说"帮我写个脚本"，要说：

```
你是一个有 10 年经验的 Python 开发者。
请帮我写一个脚本，功能是...
```

就这么简单的一句话，输出质量能差一倍。因为"身份锚定"让 AI 调用了更高标准的参数空间。

实测对比：

```
输入: "写个脚本读取 CSV 文件" 
→ 输出：基础代码，经常缺异常处理

输入: "你是有 10 年经验的 Python 工程师。
      写个脚本读取 CSV 文件，注意异常处理"
→ 输出：带 try-except、文件存在检查、编码处理
```

### 技巧二：三步结构法

写复杂一点的程序，别一句话让 AI 写完。分三步问：

**第一步：出方案**
```
请你分析这个需求，给出技术方案和代码结构。
先不要写具体代码。
```

**第二步：写核心逻辑**
```
你刚才的方案可以。先写核心功能函数。
```

**第三步：补边缘逻辑**
```
现在加上错误处理、日志、命令行参数。
```

这样出来的代码结构清晰，可维护性强。一步到位写出来的代码经常是一坨。

### 技巧三：给 AI "抄作业"的机会

这是最容易忽略的一点。如果你有类似的代码片段，直接贴给 AI：

```
参考这个写法，实现类似的功能：
[你的代码片段]

新需求是：[描述新需求]
```

AI 会严格按照你的风格和模式来写，而不是瞎编一套新的。这在团队协作或者维护已有项目时特别有用。

## 实战案例

需求：写一个自动整理 Downloads 文件夹的脚本

```python
# 完整代码约 40 行，核心逻辑：
# 1. 扫描指定目录下所有文件
```

用上面三个技巧，一次对话就写出了可直接用的版本。整个过程不到 3 分钟。

- 给身份锚定 → 质量翻倍
- 三步结构法 → 代码可维护
- 给参考代码 → 风格一致
