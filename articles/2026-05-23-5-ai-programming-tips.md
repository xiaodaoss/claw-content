# 5 个反直觉的 AI 编程技巧——越离谱，越管用

**摘要**：你还在让 AI "写个函数"？试试这 5 个反直觉的提示词技巧——让 AI 帮你写 Bug、故意不说人话、甚至跟它吵架，结果反而更有效率。全是实操踩坑经验。

---

## 1. 让 AI 先写 Bug

直觉上，我们想要"一次到位"的完美代码。但实际测试下来，**先让 AI 写一个有 Bug 的版本比直接要正确答案快得多**。

**为什么？**
- 人类更容易在"纠正"时精确描述问题，而不是"从头定义"需求
- AI 在修复上下文中的表现往往优于生成上下文

实操：
```
❌ "用 Python 写一个二分查找"
✅ "先写一个二分查找，但故意在边界条件上留 Bug，然后告诉我怎么修"
```

结果：AI 先生成一个"错误"版本，然后自我审查修复过程，**同时教会了你边界条件的常见陷阱**。

## 2. 用"反向语言"跟 AI 说话

这不是玩笑。当你遇到 AI 反复给出错误方案时，**让 AI 告诉你"不要怎么做"**，效果出奇好。

实操对比：
```
❌ "如何用 pandas 优化这串循环？"
✅ "列出 3 个常见的 pandas 性能优化错误，然后展示它们的正确写法"
```

反向约束迫使 AI 从"踩坑"角度思考，而不是泛泛而谈最佳实践。对于有经验的开发者来说，这种"避坑清单"比"最佳实践列表"有用 10 倍。

## 3. 跟 AI 吵架

听起来很蠢，但有效。当 AI 给出一个你不确定的方案时，**让 AI 反驳自己**。

实操：
```
prompt = "对于这个 SQL 查询优化，给出 3 种方案。然后从执行效率、可维护性、可扩展性三个角度攻击每种方案，选出最差的一种并解释为什么它反而最常用。"
```

这种"辩论模式"会触发 AI 的深层推理。你得到的不是"一个方案"，而是"决策树 + 权衡分析"。

## 4. 要求代码有"性格"

AI 的默认输出是"教科书风"——稳定但无趣。稍微加点性格约束，代码可读性直接翻倍：

```
"用 Python 写一个文件监控脚本。
风格要求：
- 变量名像 Unix 哲学一样短
- 每段代码块前写一句注释解释为什么这么写，而不是在写什么
- 错误处理写得像跟同事解释：'这个可能会炸，我是这么兜底的'
```

**实测效果**：AI 的输出会更接近"有经验的同事写的代码"而非"作业代码"。

## 5. 用"极端值"测试（不要用例）

你不需要写完整的测试用例。让 AI 用极端值"脑力测试"你的逻辑：

```
"下面这段代码，给我找出它会在哪 3 种极端输入下崩溃：
[贴代码]
别修，只告诉我哪里会炸，用什么输入可以复现"
```

这比直接让 AI 写测试快得多，而且更适合代码审查场景。你拿到"炸点清单"后，再决定哪些值得修。

---

## 本周实验结论

这 5 个技巧的共同逻辑是：**不要跟 AI 的"默认模式"走**。

AI 默认是"好好先生"——它倾向于给出最安全、最中庸的回答。你越让它"反常"，它输出越有价值。
